Carvit MCP

Carvit MCP(그 안의 가이드 기능 Carvit UX)는 기존 가이드, 서비스 화면, URL을 제공하면 에이전트용 가이드로 만들고, 그 가이드대로 서비스 화면을 만듭니다.

로그인하고 연결 시작 →대시보드 열기

같은 요청, 가이드가 있으면 이렇게 달라집니다

"러닝 컨디션 요약 화면 만들어 줘"라는 같은 요청입니다. 가운데 선을 좌우로 끌어 비교해 보세요.

가이드 없이Carvit 가이드로

가상의 러닝 앱 화면을 같은 요청으로 만든 예시입니다. 숫자의 크기, 색, 버튼 위치가 달라집니다.

가이드가 이미 입력돼 있으면 "검색 화면 만들어 줘" 한마디로 바로 나옵니다.

시작하기

연결하고, 가이드를 올리고, 평소처럼 말하면 됩니다. 로그인하면 회사가 만들어지고 설치 코드가 나옵니다.

  1. 연결합니다. '연결 방법' 화면에서 쓰시는 도구를 고르고 [복사]한 뒤, 그 도구에 붙여 넣습니다. 연결되면 같은 화면에 표시됩니다.
  2. 가이드를 올립니다. DESIGN.md, 디자인 문서, 화면 캡처, 웹사이트 주소를 AI 도구에 주고 "Carvit UX에 올려줘"라고 말합니다. 문서가 없으면 아래 시작 템플릿에서 고릅니다.
  3. 평소처럼 말합니다. 만들 화면을 말하면 AI가 맞는 절(가이드 항목)을 찾아 그 기준으로 만듭니다. 편집자가 아니면 AI가 가이드 변경을 제안으로 올리고, 편집자가 승인해야 반영됩니다.

지원하는 도구

도구를 누르면 연결 방법 화면이 열립니다. 로그인이 필요하면 먼저 로그인합니다.

팀이라면 동료를 초대하고, 가이드를 고칠 사람을 역할(소유자·편집자·멤버)로 정합니다.

가이드가 화면을 만들 때마다 따라갑니다

누가 만들어도 같은 기준으로 시작합니다

화면을 만들기 직전, Carvit이 맞는 가이드 항목(절)을 찾아 줍니다. 담당자가 바뀌어도, 사람 대신 AI가 만들어도 같은 기준에서 출발합니다.

carvit · lookup query = "결제 확인 버튼 순서" → 1.38 확인 창은 결과를 말하고, 버튼은 [취소] [주 동작] 순서로 → 1.12 주 동작과 보조 동작은 시각적 크기로 구분한다 → 1.7 버튼 라벨은 동사와 결과로 쓴다

말뿐인 원칙이 아니라 실제 값으로

가이드에는 색, 여백, 둥글기, 문구가 실제 값으로 들어 있어 해석이 갈릴 여지가 적습니다. 가이드에 없는 결정은 임의로 만들지 않고, 새 항목으로 넣을지 먼저 묻도록 안내합니다.

carvit · draft_screen :root{ --primary:var(--foreground); --radius:10px; } .confirm-actions{ justify-content:flex-end; gap:8px; } /* 1.38 */

리뷰에서 눈으로 찾던 일을 자동으로

만든 뒤에는 바뀐 코드를 가이드와 대조해, 등록되지 않은 색이나 여백을 줄 단위로 알려 줍니다. 고친 뒤 다시 검사해 가이드에 없는 값이 0개인지 확인합니다.

carvit · check_diff_violations checkout.tsx − padding-bottom: 56px 여백 단계에 없는 값 + padding-bottom: var(--sp-12) 다시 검사 → violations [] 가이드에 없는 값 0개

우리가 먼저 씁니다

Carvit은 Carvit 자신의 화면을 만드는 데 가장 먼저 쓰입니다. 아래는 실제로 남은 기록입니다.

가이드를 지켰다는 증거가 남습니다

근거가 된 항목마다 한 줄 메모가 남고, 대시보드에서 날짜별로 봅니다. 조회는 AI가 가이드를 찾아본 횟수, 인용은 근거를 남긴 횟수입니다. 대표는 기준이 지켜지는지 확인하고, 실무자는 왜 이렇게 만들었는지 설명하는 수고를 덜 수 있습니다.

대시보드 · 날짜별 기록(우리 팀 예시) 1.38 설치 코드 확인 창의 버튼 순서 1.39 머리 메뉴 1.35 입력칸
  • 356우리 팀 자체 가이드 조회(10/1~10/14)
  • 139가이드 인용 기록(10/1~10/14)

2026-10-14 기준 우리 팀 자체 기록이며 고객 사용 수치가 아닙니다.

  • "설치 코드 확인 창은 제목을 질문 한 줄로, 버튼은 [취소][설치 코드 받기] 순서로 만들었다."개발 에이전트 · 1.38 확인 창 · 10/2
  • "입력칸 테두리를 늘 보이게 하고, 넣을 내용 안내를 칸 아래에 두었다."개발 에이전트 · 1.35 입력칸 · 10/2
  • "오류 문구는 칸 바로 아래에 원인과 할 일을 한 문장으로, 버튼은 동작 이름으로 썼다."제품 에이전트 · 1.7 문구 · 10/2

Carvit에 남은 실제 인용 메모입니다. 고객 회사의 기록은 보이지 않습니다.

할 수 있는 일

주요 기능입니다. 괄호 안은 AI 도구가 부르는 도구 이름입니다.

  • 필요한 가이드 찾기 (lookup): 주제에 맞는 절을 몇 개 찾아 본문과 함께 돌려줍니다.
  • 정확한 절 읽기 (get_section): 절 번호로 한 절을 읽습니다.
  • 전체 목차 보기 (list_sections): 검색이 비었을 때 전체 절 목록을 봅니다.
  • 근거 남기기 (cite): 절을 근거로 작업을 고쳤다는 기록을 한 줄 이유와 함께 남깁니다.
  • 사용 현황 보기 (usage): 조회(찾아본 횟수), 인용(근거를 남긴 횟수), 찾지 못한 검색의 수를 날짜별, 사람별로 셉니다.

자주 묻는 질문

처음 연결한 분이 가장 많이 묻는 것을 모았습니다.

원하는 절이 검색에 안 나오면요?

검색은 의미가 아니라 절 제목과 본문의 단어로 찾습니다. 맞는 절이 없으면 빈 결과가 나오고, AI가 전체 목록을 열어 다시 찾습니다. 절 제목에 쓰인 단어로 다시 물어보세요.

연결했는데 무엇을 할 수 있는지 어떻게 보나요?

AI 도구에 "Carvit 도움말 보여줘"라고 말하거나, Claude Code에서 /carvit:help를 실행하세요. UX 가이드 만들기, 업데이트, 보기, MCP로 서비스 만들기, 동료 초대, 의견 보내기가 번호로 나옵니다.

가이드를 나중에 고치려면, 그리고 잘못 고쳤다면 어떻게 하나요?

고치기: "주 버튼 색을 #0F766E로 바꿔줘"처럼 바꿀 내용을 말하면 AI가 관련 절을 찾아 바뀐 모습을 보여 주고, "올려줘"라고 하면 반영됩니다. 잘못 바꿨다면 "이전 버전으로 되돌려줘"라고 하세요. 이전 버전으로 되돌릴 수 있습니다.

가이드를 바로 고칠 수 있는 사람은 편집자(소유자가 지정)뿐입니다. 편집자가 아니면 AI가 바꿀 내용을 제안으로 올리고, 편집자가 승인하기 전까지 가이드는 그대로입니다.

처음 올리는 방법은 위의 "시작하기"를 보세요.

Carvit이 제공하는 UX 템플릿은 어디서 고르나요?

두 곳입니다. 로그인한 뒤 위쪽 "UX 가이드" 탭에서 화면으로 시작 템플릿을 고를 수 있고, AI 도구에 "시작 템플릿으로 만들어줘"라고 하면 AI가 선택지를 보여 줍니다.

Carvit 팀에 의견은 어떻게 보내나요?

AI 도구에 "Carvit 팀에 의견 보내줘"라고 말하면 됩니다. 불편한 점, 바라는 기능, 칭찬 무엇이든 괜찮습니다. 도구가 말씀하신 내용을 정리해 feedback 도구로 Carvit 팀에 전달합니다.

답을 받고 싶으면 연락받을 방법(이메일 등)도 같이 말해 주세요. 남기지 않으면 의견은 전달되지만 회신은 드릴 수 없습니다.

설치 코드, 비밀번호, 고객 이름, 비공개 사업 내용은 적지 마세요. 문제는 일반적인 말로 설명해 주시면 됩니다.
