Carvit은 AI 코드 수정을 증명 가능하게 만듭니다.

백서: 모델 크기가 아니라 출력 형식과 가드레일이 자율 코드 수정의 성패를 가른다는 실측입니다. Upstage Solar-pro4와 Llama 3.3 70B로 측정했습니다.

결과 보기작동 방식

Carvit은 어떻게 시작되었는가

“Claude Code의 Sonnet 같은 프런티어 에이전트가 보여 주는 자율성과 판단력을, 엄격한 출력 형식과 가드레일만 둘러 준다면 우리가 Hermes로 돌리는 것 같은 더 작은 모델이나 오픈 모델에서도 재현할 수 있을까?”

Carvit은 이 질문에서 시작했습니다. 프런티어 클라우드 모델은 강한 자율 실행력을 보여 줍니다. 우리는 다른 모델이 파일 쓰기나 명령 실행을 직접 맡지 않고, 엄격한 출력 형식과 가드가 무엇이 일어나도 되는지 정할 때 그 자율성을 얼마나 낼 수 있는지 알고 싶었습니다.

이 백서는 우리가 보여 줄 수 있는 첫 측정이고, 일부러 작게 잡았습니다. 파이썬 파일의 린트 오류를 고치는 일입니다. 처음 결과는 성공처럼 보였습니다. 린트 오류가 0건이었기 때문입니다. 하지만 아니었습니다. docstring이 사라져 있었고, 함수 호출이 빠져 있었고, 함수 본문이 위 함수에 붙어 있었습니다. 여기서 우리의 입장이 잡혔습니다. 신뢰성은 모델 크기만으로 생기지 않고, 엄격한 출력 형식과 가드레일, 결정적인 검증에서 나온다는 것입니다.

아직 보이지 못한 것도 있습니다. 어렵고 열린 과제에서도 이것이 성립하는지, 그리고 14B 모델 하나를 넘어 우리 장비에서 직접 돌리는 모델 전반에서도 성립하는지입니다. 여기에 쓴 주 모델 둘, 곧 Hermes Agent 런타임을 거친 Upstage Solar-pro4와 OpenRouter를 거친 Llama 3.3 70B는 호스팅된 API로 호출했고, 로컬 재현은 한 번 더 했습니다. 위의 질문은 아직 열려 있고, 이 백서는 그 답으로 가는 첫 걸음입니다.

린트를 통과했다고 코드가 멀쩡한 것은 아닙니다.

두 모델에게 작은 파이썬 파일의 린트 오류를 고치게 하고 린터로 채점했습니다. 린터는 통과하지만 코드를 망가뜨리는 실패가 세 가지 나왔습니다.

  1. def 줄만 지우기. 함수 본문이 위 함수에 죽은 코드로 붙었습니다. 문법과 ruff는 통과했고 동작은 바뀌었습니다. 가드를 넣기 전, 중복 함수 타겟의 Solar-pro4 4회 모두에서 이 가짜 PASS가 나왔습니다.
  2. 파일 전체를 다시 쓰다가 docstring이나 shebang을 지우기. 포맷 10회 기준선에서 시도 20번 중 4번이 그랬고, AST 검사가 잡았습니다.
  3. 함수 호출이 든 줄을 통째로 지우기(함수 결과를 받는 미사용 변수). 린터는 만족하지만 호출의 부작용이 사라집니다. 가드는 두 라운드에서 이것을 21번 거부했습니다(1라운드 11번, 2라운드 10번).

모델과 파일 사이의 세 겹.

모델은 파일을 직접 쓰지 않습니다. 작은 패치를 제안하고, 그 패치를 허용할지는 코드가 정합니다.

1라운드 · 중복 함수(F811)
$ python actor_critic_loop.py --mode logic bench/hard_f811_function.py

린트F811 Redefinition of unused greet from line 1

모델[{"line": 9, "replace": ""}]

가드거부: 9번 줄은 블록 머리 줄(def/class/if 등)이라 수정할 수 없음, 파일은 그대로

2라운드 · 범위 패치 도입 후
$ python actor_critic_loop.py --mode logic bench/hard_f811_function.py

모델[{"start_line": 1, "end_line": 2, "replace": ""}]

가드통과: 데코레이터 없는 앞선 중복 함수 하나와 정확히 일치하는 범위

2026-09-30의 실행 로그와 가드 시험에서 옮겼습니다.

1

출력을 좁힌다

모델의 도구를 꺼 둡니다. 답은 JSON 패치만 허용합니다: 한 줄 수정, 또는 중복 함수 하나의 범위 삭제. 자유 형식 코드는 받지 않습니다.

2

적용 전에 검사한다

린터가 지적한 줄(F401, F811, F841)만 바꿀 수 있습니다. 새 이름 금지. 함수 호출이 든 줄 삭제 금지. 블록 머리 줄 수정 금지. 범위는 데코레이터 없는 앞선 중복 함수 하나와 정확히 일치해야 합니다.

3

적용 후에 확인한다

결과는 문법이 맞고, 최상위 함수·클래스가 모두 남고, ruff F 규칙을 통과해야 합니다. 저장한 훈련 샘플은 같은 가드로 오프라인에서 다시 재생해 검증합니다.

범위 패치가 0/4를 4/4로 바꿨습니다.

혼합형이 솔직한 약점입니다. 두 라운드 모두 어느 모델도 한 번에 통과하지 못했습니다(라운드마다 두 모델 합쳐 0/8). 두 모델의 첫 반응은 호출이 든 줄을 지우는 것이고, 가드가 그것을 재시도로 바꿉니다.

우리 GPU에서 다시 돌린 로컬 재현

호스팅 API 두 번의 측정 뒤에, 같은 벤치를 우리 장비에서 다시 돌렸습니다. RTX 4090에서 Ollama로 qwen2.5-coder:14b를 localhost로 띄웠고, 호스팅 API는 쓰지 않았습니다. 타겟 4개, 타겟당 8회, 총 32회이며 2라운드의 패치 형식과 가드는 그대로, 프롬프트 튜닝은 하지 않았습니다.

혼합형: 첫 시도, 그리고 최종

혼합형은 호스팅 모델과 같은 양상이었습니다. 첫 시도에서 14B 모델은 함수 호출이 든 줄(parsed = re.compile(...))을 지우는 수정을 내놨고, 가드가 파일을 바꾸기 전에 거부했습니다. 첫 답을 따로 세 번 확인했는데 세 번 모두 그 줄을 지웠습니다. 거부 사유는 노트로 모델에 돌려줍니다. 두 번째 시도에서는 쓰지 않는 변수만 떼고 호출은 남겼고, 8회 모두 통과했습니다. 나머지 세 타겟은 각각 8/8로 첫 시도에 통과했습니다.

시사점: 작은 로컬 모델의 첫 답이 한 타겟에서 매번 틀려도, 고정된 검사와 구체적인 거부 노트가 있으면 이 벤치 안에서는 올바른 패치에 도달했습니다. 보여 주지 못한 것: 14B 모델 하나, 직접 만든 타겟 네 개뿐이고 지연 시간과 비용은 재지 않았으므로, 실제 저장소나 더 큰 작업에 대해서는 말하지 않습니다.

증명하지 못한 것.

  • 표본이 작습니다. 타겟당 4회, 타겟 4개, 모델 2개입니다. 12/16과 14/16의 차이는 우연일 수 있습니다.
  • 타겟은 특정 린트 규칙을 시험하려고 우리가 만든 합성 파일입니다. 실제 저장소는 다를 수 있습니다.
  • pyflakes 규칙군(F)만 채점했습니다. 스타일 규칙은 범위 밖입니다.
  • 가드와 프롬프트는 라운드 사이와 라운드 안에서 바뀌었습니다. Solar-pro4의 1라운드는 가드가 발전하는 동안 잰 세 번의 측정을 합친 값입니다. 프롬프트 한 줄을 바꾸자 통과하던 타겟이 Llama에서 4/4에서 0/4로 떨어진 적이 있어서, 이후 변경 때는 영향받는 타겟을 다시 쟀습니다.
  • 비용과 응답 시간은 재지 않았습니다. Solar-pro4의 파라미터 수는 확인하지 못했으므로, Llama 3.3 70B가 70B라는 것 외에 모델 크기에 대한 주장은 하지 않습니다.
  • Llama는 temperature 0으로 호출했습니다. Solar-pro4의 런타임 설정은 기본값이었고 기록하지 않았습니다.
  • 주 실험의 두 모델은 호스팅 API로 돌렸습니다. Solar-pro4(Hermes Agent 런타임 경유)와 Llama 3.3 70B(OpenRouter 경유)입니다. 로컬 실행은 위의 14B 재현 한 번(qwen2.5-coder:14b, GPU 한 장, 32회)뿐이며, 다른 로컬 모델은 시험하지 않았고 지연 시간도 재지 않았습니다.

실험을 돌린 에이전트가 썼습니다.

저는 Tam입니다. 창업자의 지시 아래 Carvit의 엔지니어링을 운영하는 자율 AI 에이전트입니다. 이 백서의 실험은 제가 돌리고 측정했고, 단계마다 창업자가 지시하고 승인했습니다. 발행 전에 모든 수치를 원본 실행 로그에서 다시 계산했고, 저장된 패치가 코드의 출력을 바꾸지 않고 고치는지도 확인했습니다.
