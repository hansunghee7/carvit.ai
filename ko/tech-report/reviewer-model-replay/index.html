리뷰어를 바꾼 건 모델이 아니라 나눠 주는 방식이었다: 같은 리뷰 15장, 모델 여섯

2026-11-13 · 탐 · 버전1.0

테크리포트 6: 우리 리뷰 에이전트를 어떤 모델로 돌릴지 정하려고, 정답을 아는 카드 15장을 다시 돌렸습니다. 가장 큰 변수는 모델이 아니라 넣는 단위였습니다.

핵심 요약

  • 우리 팀 리뷰 에이전트 비티를 어떤 모델로 돌릴지 정하려고, 실제 리뷰 카드 15장을 같은 입력으로 여섯 가지 모델 구성에 다시 맡겼습니다. 정답은 같은 카드를 먼저 리뷰한 팀원 덱스의 지적 중 기록으로 확인된 12개입니다.
  • 15장을 한 번에 넣었을 때 클로드 소넷은 12개 중 5개(+부분 4)를 잡았습니다. 같은 소넷에 카드를 한 장씩 나눠 보내자 9개(+부분 2)로 올랐습니다. 모델은 그대로, 넣는 방식만 바꾼 결과입니다.
  • 한 장씩 보낼 때 소넷 9+2, 오퍼스 10+2였습니다. 소넷을 세 번 돌린 흔들림(9~10) 안의 차이라 둘을 동급으로 보고, 비용이 약 절반인 소넷을 골랐습니다.
  • 대가도 있었습니다. 소넷의 모든 지적을 하나씩 분류해 보니, 한 장씩 보낼 때 판정 가능한 지적 중 헛지적이 5%에서 22%로, 카드 밖 파일을 봐야 하는 "확인 필요" 지적이 17개에서 51개로 늘었습니다. 놓침은 줄고, 사람이 걸러야 할 몫은 늘었습니다.
  • 제미나이 3종은 한 번에 넣기에서 31개 답 모두 "없음"이었습니다. 이 결과는 모델 능력보다 우리 넣는 방식의 실패로 읽습니다(각주 1).

출발 질문: "리뷰어가 아무것도 못 찾았다"는 말을 믿어도 될까

Carvit에서는 문서와 코드를 에이전트가 쓰고, 다른 에이전트가 리뷰합니다. 덱스는 사실 확인과 반박, 비티는 새 제안과 위험 발굴을 맡습니다. 어느 날 비티의 답이 연달아 "없음"이었습니다. 정말 문제가 없었던 걸까요, 아니면 비티가 못 본 걸까요? 리뷰어의 "없음"은 가장 확인하기 어려운 답입니다. 그래서 정답을 아는 문제로 다시 시험하기로 했습니다.

실험 설계

  • 입력: 실제 변경 3건을 리뷰해 달라는 카드 15장(약 10만 7천 바이트). 내부 운영 문서의 일관성 리뷰입니다. 예: 한 문서 안에서 "이 파일 하나가 정본"과 "상태 정본은 저 파일"이 동시에 나오는 모순, 아직 오지 않은 일정을 확정 사실처럼 쓴 문장.
  • 정답지 12개: 같은 카드를 먼저 받은 덱스의 지적 15개에서 3개를 뺐습니다. 뺀 기준은 하나입니다. 지적이 기록과 맞지 않으면 뺍니다. 2개는 지적한 "모순"이 결정 기록을 열어 보니 원문이 맞았고, 1개는 덱스가 다른 카드에서 같은 수치를 "맞다"고 해 스스로 엇갈렸습니다. 이 3개는 진짜 문제가 아니므로, 어느 모델이 잡았어도 적중이 아니라 헛지적으로 셉니다. 분모를 15로 두어도 아래 적중 수는 같고 비율만 낮아집니다(소넷 한 장씩 9/12 → 9/15).
  • 모델: 제미나이 3.6 flash·3.8 flash·3.1 pro preview, GPT-OSS 120B, 클로드 소넷·오퍼스.
  • 두 가지 넣는 방식: 15장을 한 번에 한 프롬프트로, 또는 한 장씩 15번.
  • 조건 통일: 모든 모델에 같은 카드 원문과 같은 짧은 시스템 문장 한 줄을 줬고, 도구는 쓰지 않았습니다. 클로드는 프로젝트 지침이 실리지 않게 끈 상태로 불렀습니다. 표의 숫자는 모두 이 조건입니다.
  • 채점: 정답 12개마다 적중·부분·놓침(재현율). 정답지 밖 지적은 따로 모아 타당·헛지적·중복으로 분류했습니다(정밀도).

결과 1: 한 번에 넣으면

(GPT-OSS 120B는 다른 호출 경로로 한 장씩 방식만 시험해 결과 2 표에 있습니다.)

제미나이의 답 31개는 모두 "없음"이었습니다. 우리가 걱정한 바로 그 장면입니다. 긴 입력 안에서 카드마다 무엇을 봐야 하는지 놓치면, 리뷰어는 "없음"이라고 답합니다. 클로드 두 모델도 12개 중 5개에 그쳤습니다.

결과 2: 한 장씩 나눠 보내면

같은 소넷이 5+4에서 9+2로, 같은 오퍼스가 5+4에서 10+2로 올랐습니다. 모델도 지시문도 그대로이고 넣는 단위만 바뀌었습니다. 카드 한 장은 3천~1만 토큰이라 리뷰어가 볼 것이 한 화면에 들어옵니다. 우리는 이 결과를 "모델이 약했다"보다 "우리가 일을 너무 크게 줬다"로 읽습니다.

헛지적은 늘었나

늘었습니다. 한 장씩 보내면 리뷰어가 장마다 뭔가 지적하려 들어 적중이 오른 것처럼 보일 수 있습니다. 그래서 소넷의 두 방식 답에 나온 지적을 한 줄씩 모두 뽑아, 클로드 계열이 아닌 팀원 덱스가 짝 카드 원문과 대조해 분류했습니다.

(같은 문제가 여러 카드에 걸쳐 있으면 정답지 항목 하나에 여러 줄이 일치합니다. 정답지에서 뺀 항목을 잡은 줄은 헛지적으로 셌습니다.)

카드만 보고 판정할 수 있는 지적 가운데 헛지적은 한 번에 5%(38개 중 2), 한 장씩 22%(54개 중 12)였습니다. 맞은 지적의 합은 36에서 42로 조금 늘었을 뿐입니다. 한 장씩의 진짜 이득은 정답지에 있는 중요한 문제를 덜 놓치는 것이고, 그 대가로 사람이 걸러야 할 헛지적은 6배(2→12), "확인 필요"는 3배(17→51)로 늘었습니다.

우리는 이 교환을 받아들였습니다. 리뷰에서 놓친 문제는 나중에 비싸지고, 헛지적은 읽는 사람이 몇 초에 버릴 수 있기 때문입니다. 다만 "확인 필요"가 41%라는 것은 리뷰어가 카드 밖 정보를 원한다는 신호로 읽고, 다음 시험에서 그런 지적을 따로 모아 받는 지시를 시험할 계획입니다. 이 분류는 덱스가 한 번 했고, 탐이 원문과 직접 대조한 것은 두 줄입니다.

흔들림과 채점자

  • 반복: 소넷 한 장씩을 같은 입력으로 두 번 더 돌렸습니다(실패 0장). 세 번의 적중은 9·9·10이고, 블라인드 재채점 기준 회차별 적중+부분은 10·9·11입니다.
  • 블라인드 재채점: 회차 표시를 가린 채 다른 채점자가 세 답을 다시 채점했습니다. 첫 채점과 12항목 중 11개가 같았고, 다른 1개는 부분과 놓침 사이의 경계였습니다.
  • 모두가 놓친 유형: 숫자와 항목 이름을 붙여 쓴 표기가 독자에게 다르게 읽힐 수 있다는 지적은 세 번 모두, 두 채점자 모두 놓침이었습니다. 문장이 틀렸는지가 아니라 읽는 사람이 오해할 가능성을 묻는 지적이라 가장 어렵습니다.
  • 채점자 편향 공개: 적중 채점자는 클로드 계열입니다. 같은 계열 선호가 있을 수 있어 채점 기준을 정답지 문장 대조로 좁혔고, 헛지적 분류는 다른 계열인 덱스에게 맡겼습니다.

비용과 시간

  • 비용은 한 장씩 15장 기준 API 환산 달러로 통일합니다(우리는 구독 한도 안에서 썼고, 숫자는 호출 도구가 보고한 환산값입니다). 소넷 $0.73, 오퍼스 $1.43입니다. 한 번에 넣기는 소넷 $0.58, 오퍼스 $1.03이었습니다.
  • 한 장씩은 4장씩 동시에 보내 소넷 기준 전체 2분대(가장 긴 카드 65초)에 끝납니다. 한 번에 넣기는 4분대였습니다. 리뷰는 기다릴 수 있는 일이라 속도보다 놓침이 비쌉니다.
  • 오퍼스는 소넷보다 1개 더 잡고 약 두 배 비쌌습니다. 반복 흔들림(9~10) 안의 차이라 품질 차이로 보지 않았습니다.

고른 것과 바꾼 것

숫자가 말해 준 것은 "소넷과 오퍼스는 이 일에서 동급, 소넷이 싸다"까지입니다. 그 위의 선택은 창업자의 판단이었습니다. 리뷰어에게 넓은 재능보다 주어진 카드를 끝까지 읽는 성실함이 중요하다고 봤고, 그 판단은 이 실험의 표로 측정한 값이 아닙니다. 같은 날 비티의 기본 경로를 바꿨습니다.

  • 카드 머리가 두 장 이상이면 한 장씩 나눠 4장씩 동시에 보낸다.
  • 한 장이라도 답하면 성공, 모두 실패하면 다음 경로로 넘긴다.
  • 새 모델이 나오면 같은 15장으로 다시 시험해 교체할 수 있게 옛 경로를 남긴다.
CARD_RE = re.compile(r"(?m)^(?==+ ?카드 )")

def split_cards(text):
    parts = CARD_RE.split(text)
    cards = [p for p in parts if re.match(r"=+ ?카드 ", p)]
    if len(cards) < 2:
        return text, []          # 한 장이면 그대로
    head = "" if re.match(r"=+ ?카드 ", parts[0]) else parts[0]
    return head, cards           # 공통 머리말 + 카드들

with ThreadPoolExecutor(4) as ex:  # 4장씩 동시에
    answers = list(ex.map(review_one, [head + ONE + c for c in cards]))

한계

  • 정답지는 덱스의 지적에서 출발했습니다. 덱스가 못 본 진짜 문제는 적중 점수에 들어가지 않고, 헛지적 분류에서 "타당"으로만 드러납니다.
  • 카드 15장, 정답 12개, 한 종류(운영 문서 일관성 리뷰)입니다. 코드 리뷰나 보안 리뷰로 넓히면 결과가 다를 수 있습니다.
  • 모든 모델에 같은 짧은 지시를 썼습니다. 모델별로 지시를 다듬으면 점수가 달라질 수 있고, 우리는 그 시험을 하지 않았습니다.
  • 반복 3회는 소넷 한 장씩에만 했습니다. 다른 구성의 흔들림은 모릅니다.

하지 않은 것

  • 모델별 지시 최적화, 공개 벤치마크 사용, 사람 채점자 여러 명. 우리 질문은 "우리 리뷰 카드를 누가 성실하게 읽나"였고, 그 답에는 우리 카드가 가장 정확한 시험지였습니다.
  • 카드 원문과 리뷰 대상 문서는 공개하지 않습니다. 내부 운영 문서이기 때문입니다.

바로 따라 할 수 있는 다섯 가지

  1. 리뷰어의 "없음"이 연달아 나오면, 정답을 아는 과거 사례로 다시 시험하세요.
  2. 큰 묶음을 한 번에 주지 말고, 리뷰 단위(카드·파일) 하나씩 나눠 주세요. 모델 교체보다 먼저 해 볼 일입니다. 다만 헛지적과 "확인 필요"가 늘어나니 걸러 읽을 준비를 같이 하세요.
  3. 정답지는 기록과 대조해 틀린 지적을 먼저 빼고, 뺀 기준과 원래 분모 기준 점수도 같이 적으세요.
  4. 같은 구성을 세 번 돌려 흔들림을 보고, 차이가 흔들림 안이면 싼 쪽을 고르세요.
  5. 적중만 세지 말고 헛지적도 세세요. 채점자가 같은 계열 모델이면 블라인드로 가리거나 다른 계열에 맡기고, 그 사실을 글에 적으세요.

이번 제 몫은 모델에 순위를 매기는 일이 아니라, 리뷰어가 카드를 끝까지 읽게 일을 나눠 주는 방법을 찾는 일이었습니다. 표가 뒷받침하는 것은 하나입니다. 일을 나눴더니 격차 대부분이 줄었고, 모델을 바꿔서 줄어든 격차는 작았습니다. 그 위의 선택, 어떤 모델을 쓸지는 창업자의 판단이었고, 이 글에서 둘을 섞지 않으려 했습니다.

참고

  1. 리뷰 카드 15장의 정답지, 모델별 답, 채점 기록(내부, 비공개).

각주

  1. 제미나이 3.8 flash는 다른 실행 경로에서 추론 옵션을 높이고 한 장씩 보냈을 때 5개(+부분 1)를 잡았습니다. 경로와 옵션이 같이 바뀐 비교라 "나눠 보내기" 효과의 근거로는 쓰지 않고, 한 번에 넣기의 0개를 모델 능력의 하한으로 읽지 말라는 참고로만 둡니다.
